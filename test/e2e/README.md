# E2E smoke harness (Playwright)

Foundation for the **no-regression contract** of the UX overhaul. Each
PR that ships a UI change adds 1–3 specs here covering its surface so
the regression-map's 85 load-bearing features stay green.

## Running

```bash
npm run test:e2e            # headless
npm run test:e2e:headed     # watch it run
```

The first run downloads Chromium headless-shell to
`~/Library/Caches/ms-playwright`. CI pre-installs via `npx playwright install chromium`.

The config (`playwright.config.mjs`) launches a fresh `node server.js`
on port `4011` with **no OAuth env vars** so `AUTH_ENABLED=false` and
the gate is bypassed. `STARBHAI_ADMIN_PASSWORD`-gated surfaces still
treat every session as admin in this mode — admin-403 paths are
covered separately (see "Admin-gating" below).

boot (Yahoo price timeouts, earnings JSON missing). Tests are
**self-skipping**, not failing, so PR 0 lands green even on minimal
fixtures.

## Adding a spec for your PR

1. Drop the spec in `test/e2e/` named `<surface>-<behaviour>.spec.mjs`.
2. Import the shared helpers from `./helpers/app.mjs` (`gotoApp`, `switchTab`,
   `waitForPicksLoaded`).
3. Add a row to the table above.
4. Reference the regression-map IDs you cover in the spec docstring.

## Admin-gating (deferred from PR 0)

`/api/earnings/*` and `/api/earnings/backtest` enforce admin via
`requireEarningsAdmin` only when `AUTH_ENABLED=true`. To exercise the
non-admin-403 path, set:

```bash
STARBHAI_SESSION_SECRET=test-secret \
GOOGLE_CLIENT_ID=test \
GOOGLE_CLIENT_SECRET=test \
GOOGLE_OAUTH_REDIRECT_URI=http://localhost:4011/callback \
npm run test:e2e
```

…then sign a session cookie in the spec for both an admin and non-admin
fixture user. This work is captured as a follow-up; see PR plan §13 V11.7.

## Fixtures

`test/e2e/fixtures/groww-sample.xlsx` is generated by:

```bash
node test/e2e/helpers/build-fixture-xlsx.mjs
```

Re-run if you change the shape. The file is gitignored so check it in
only if the schema diverges from a real Groww export.

## Telemetry capture during tests

Each spec runs against the real `POST /api/telemetry` handler. Events
land in `data/telemetry/events.ndjson` (gitignored). Inspect a run:

```bash
tail -n 50 data/telemetry/events.ndjson | jq -s 'group_by(.event) | map({event:.[0].event, n:length})'
```

NS-1 (Time-to-Verdict) is computed as
`ts(verdict_visible) − ts(page_load)` per session.
